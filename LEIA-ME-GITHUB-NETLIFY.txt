CORREÇÃO PARA NETLIFY VIA GITHUB

Esta versão foi preparada para evitar o erro "Page not found".

Arquivos principais na raiz do repositório:
- index.html
- netlify.toml
- assets/hero-reflexiva.png
- netlify/functions/generate-diagnosis.mjs

Configuração na Netlify:
- Build command: deixe vazio
- Publish directory: deixe vazio ou use "."
- Functions directory: netlify/functions

Variáveis obrigatórias:
- OPENAI_API_KEY = sua chave da OpenAI
- Também são aceitos: OPENAI_KEY, OPENAI_SECRET_KEY ou OPENAI_TOKEN

Opcional:
- OPENAI_MODEL = gpt-5.5

Formulário:
- O formulário usa Netlify Forms nativo.
- Nome no painel da Netlify: anamnese-hero
- Existe um formulário invisível de detecção no início do HTML para a Netlify cadastrar o Forms durante o deploy.
- O wizard visual envia para o mesmo form-name: anamnese-hero.
- O Forms só aparece no painel depois de um deploy novo em Production com o index.html publicado.
- Para receber por e-mail, configure em Netlify > Forms > anamnese-hero > Form notifications.

Depois de subir no GitHub:
1. Faça commit incluindo index.html, netlify.toml, assets e netlify/functions na raiz.
2. Na Netlify, acione "Trigger deploy" > "Deploy site".
3. A página deve abrir pela raiz do domínio.

Se ainda aparecer Page not found:
- Verifique se index.html está na raiz do repositório no GitHub.
- Verifique se netlify.toml está na raiz do repositório.
- Em Site configuration > Build & deploy, confirme que Publish directory não aponta para uma pasta antiga.

Se a IA disser que a chave não está configurada:
- Confirme que a variável está no mesmo site da Netlify publicado.
- Confirme que está em Site configuration > Environment variables.
- Depois de salvar a variável, faça novo deploy.
- Não coloque aspas na chave.

Se o Forms ainda não aparecer:
- Confirme no GitHub se o index.html da raiz contém data-netlify="true".
- Use Trigger deploy > Clear cache and deploy site.
- Veja o deploy log e procure por "Forms" ou "Detected form".
- O Forms não aparece em arquivos abertos localmente via file://.
