ANAMNESE H.E.R.O. - DEPLOY NA VERCEL

1. O QUE SUBIR

Suba para o GitHub ou arraste para a Vercel estes arquivos e pastas:

- index.html
- package.json
- vercel.json
- api/
- assets/

Este pacote nao depende mais de Netlify Forms nem de netlify/functions.

2. CONFIGURACAO DO PROJETO NA VERCEL

Ao importar o projeto na Vercel:

- Framework Preset: Other
- Root Directory: raiz do projeto
- Build Command: vazio
- Output Directory: vazio
- Install Command: vazio ou padrao

Depois clique em Deploy.

3. VARIAVEIS PARA ATIVAR A IA

Na Vercel, acesse:

Project Settings > Environment Variables

Crie:

OPENAI_API_KEY = sua chave da OpenAI

Opcional:

OPENAI_MODEL = gpt-5

Depois faca um novo deploy de producao. Variavel criada depois do deploy nao ativa no deploy antigo.

4. VARIAVEIS PARA RECEBER O FORMULARIO E AS FOTOS POR E-MAIL

A Vercel nao tem formularios nativos como a Netlify. O envio foi configurado por API e aceita tres opcoes.

OPCAO A - RECOMENDADA, SEM DOMINIO PROPRIO, USANDO GOOGLE APPS SCRIPT

Essa e a opcao mais estavel sem dominio proprio, porque a Vercel chama o Google por HTTPS. O Google salva a anamnese em uma planilha, salva JSON/fotos no Drive e tambem tenta enviar o e-mail. Mesmo que o e-mail caia em spam ou seja filtrado, os dados ficam recebidos no Google Sheets/Drive.

1. Acesse https://script.google.com
2. Crie um novo projeto
3. Apague o codigo inicial
4. Cole o conteudo do arquivo GOOGLE_APPS_SCRIPT_EMAIL.js
5. Deixe esta linha vazia:

SCRIPT_SECRET = ""

Assim voce elimina definitivamente o erro "Secret invalido".

Se um dia quiser usar segredo, coloque exatamente o mesmo valor em SCRIPT_SECRET no Apps Script e em GOOGLE_SCRIPT_SECRET na Vercel.

6. Clique em Deploy > New deployment
7. Tipo: Web app
8. Execute as: Me
9. Who has access: Anyone
10. Clique em Deploy
11. Autorize o envio de e-mail, planilha e Drive
12. Copie a URL do Web App

A URL correta precisa ter este formato:

https://script.google.com/macros/s/SEU_DEPLOYMENT_ID/exec

Nao use:

- Link do editor do Apps Script
- Link do Google Drive
- Link docs.google.com
- Deployment ID sozinho
- URL terminada em /dev

Na Vercel, configure:

GOOGLE_SCRIPT_URL = URL do Web App copiada no Apps Script
FORM_TO_EMAIL = marcosestevees@icloud.com
FORM_CC_EMAIL = outro-email-de-teste@gmail.com

FORM_CC_EMAIL e opcional, mas recomendado no primeiro teste. Assim voce confirma se o Google enviou e se o iCloud colocou a mensagem em spam/lixo ou bloqueou a entrega.

Nao configure GOOGLE_SCRIPT_SECRET enquanto SCRIPT_SECRET estiver vazio no Apps Script.

Depois faca novo deploy na Vercel.

ONDE VER AS RESPOSTAS SE O E-MAIL NAO CHEGAR

Depois do primeiro envio real, o Apps Script cria automaticamente:

- Uma planilha chamada Anamneses H.E.R.O.
- Uma pasta no Drive chamada Anamneses H.E.R.O. - Fotos e JSON

Procure esses nomes no Google Drive da conta que publicou o Web App. Essa passa a ser a fonte principal e segura dos dados.

TESTE DIRETO DO GOOGLE APPS SCRIPT

Antes de testar pelo formulario, abra o projeto no Apps Script, selecione a funcao sendHeroTestEmail e clique em Run. Depois confira:

- Caixa de entrada
- Spam
- Lixo
- Aba/promocoes, se for Gmail
- Pasta enviados da conta Google que executa o script

OPCAO B - SEM DOMINIO PROPRIO, USANDO GMAIL/ICLOUD/OUTLOOK POR SMTP

Use apenas se nao quiser usar Google Apps Script. SMTP pode falhar com mais facilidade em ambiente serverless.

Para Gmail:

SMTP_SERVICE = Gmail
SMTP_USER = seuemail@gmail.com
SMTP_PASS = senha de app do Gmail
FORM_TO_EMAIL = marcosestevees@icloud.com
FORM_FROM_EMAIL = Consultoria H.E.R.O. <seuemail@gmail.com>

Para iCloud:

SMTP_HOST = smtp.mail.me.com
SMTP_PORT = 587
SMTP_SECURE = false
SMTP_REQUIRE_TLS = true
SMTP_USER = seuemail@icloud.com
SMTP_PASS = senha especifica de app da Apple
FORM_TO_EMAIL = marcosestevees@icloud.com
FORM_FROM_EMAIL = Consultoria H.E.R.O. <seuemail@icloud.com>

No iCloud:
- SMTP_USER precisa ser o e-mail completo, por exemplo marcosestevees@icloud.com
- SMTP_PASS precisa ser a senha especifica de app gerada em account.apple.com
- FORM_FROM_EMAIL precisa usar o mesmo e-mail do SMTP_USER
- Nao coloque aspas nas variaveis da Vercel

Para Outlook/Hotmail:

SMTP_SERVICE = Outlook365
SMTP_USER = seuemail@outlook.com
SMTP_PASS = sua senha de app ou senha autorizada
FORM_TO_EMAIL = marcosestevees@icloud.com
FORM_FROM_EMAIL = Consultoria H.E.R.O. <seuemail@outlook.com>

Depois faca um novo deploy.

OPCAO B - RESEND COM DOMINIO VERIFICADO

Crie uma conta em https://resend.com, gere uma API key e adicione na Vercel:

RESEND_API_KEY = sua chave do Resend
FORM_TO_EMAIL = marcosestevees@icloud.com
FORM_FROM_EMAIL = Consultoria H.E.R.O. <seu-email-verificado@seudominio.com>

Para producao, use um remetente com dominio verificado no Resend. Se o remetente nao estiver autorizado, o envio sera recusado pelo provedor.

5. COMO TESTAR

Depois do deploy:

- Abra https://SEU-SITE.vercel.app/api/generate-diagnosis
  Deve aparecer: {"error":"Metodo nao permitido."}

- Abra https://SEU-SITE.vercel.app/api/submit-form
  Deve aparecer: {"error":"Metodo nao permitido."}

Isso confirma que as APIs existem. Em seguida, preencha o formulario completo pelo dominio da Vercel, anexe fotos pequenas ou marque o envio posterior, finalize e confira o e-mail.

6. OBSERVACAO SOBRE FOTOS

As fotos sao comprimidas no navegador antes de irem para a IA e para o e-mail. Ainda assim, evite anexar imagens gigantes. Se o envio falhar por tamanho, reduza as imagens ou envie sem fotos e use a opcao de envio posterior.
